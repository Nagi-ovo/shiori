# Surgical same-font oracle

Run from the repository root:

```sh
bun scripts/pdf-inplace/surgical-first.ts
```

Needs installed bun dependencies, Python 3, qpdf, pdftotext and the native
PDFium library in `vendor/pdfium/linux-x64/lib/libpdfium.so`. Override its
folder with `SHIORI_PDFIUM_DIR`. No Rust build or GUI is needed for this oracle.

Outputs are under `test-artifacts/pdf-inplace/surgical-first/`: before/after
PDFs, 144dpi PPM rasters, full glyph inventories, extraction, JSON acceptance
report, rerun command, and the report-only 300-page preview benchmark.

The four binary fixtures are unchanged copies of the native PDFium edit
spike's `artifacts/spike/fixtures/{happy,kerning,background,subset}.pdf`.
They use FoxitSerif from the project's PDFium test fixtures and two embedded
Liberation Sans subsets. The spike intentionally lacks ToUnicode on its
WinAnsi Type1 font. The runner now adds bfchar entries for OBSERVED source
ASCII codes only, restricted to the known SHIORI+FoxitSerif/WinAnsi fixture.
This provides extraction metadata, never proof of glyph presence; the compiler
still checks original page usage independently. No blanket ASCII bfrange or
verifiedCodes override is installed. Before and after share the same mapping.
The longer replacement is now `World Hello Hello` and the tracked replacement
is `Tracked words ahead`: the previous `Again`/`gone` introduced an unshown g.
The original binary fixtures and embedded font programs remain unchanged.
A tenth case wraps the happy page in Word-style `/P <</MCID 0>> BDC ... EMC`.
The harness never calls GenerateContent.

The TS oracle independently enumerates every raw source string code,
including Form content. It reopens the SAVED before and after PDF bytes and
re-parses their content streams/font references, comparing raw codes, font
object ids and order to the expected edit sequence. Expected and observed
output sequences are stored separately in the manifest. Regression tests
reject code and font-object substitutions even with identical Unicode/width. Python binds PDFium through ctypes, reopens every
output and checks native text, origins, embedded font-program hashes and
one-to-one font-object/handle identity. It matches untouched glyphs by font
object/code/order. Source whitespace marked generated by PDFium is retained
when it matches the next source glyph; other generated whitespace is listed
explicitly. Missing, extra, reordered or unmapped source glyphs fail the run.
Raster comparison uses exact BGRA bytes, flags=0, 144dpi and boxes declared
before rendering. Identity/forced-identity cases also require zero changed
pixels inside the box. PDFium and Poppler must both extract replacement text
and omit the old phrase. This is active extraction, not forensic redaction.

The preview prototype appends a changed page dictionary, its new content
stream, classic xref entries and `/Prev` to an unencrypted 300-page fixture.
The full save uses pdf-lib defaults (object streams enabled, as in the app).
Both timing paths include allocation of the complete output and omit parse
and disk time. Seven measured runs follow one warmup; the machine is recorded.
Both outputs are checked by qpdf, pdf-lib and native PDFium, including first
and last page isolation. The prototype is not application infrastructure and
has no encryption, signature, xref-stream or production-save contract.

Stage 1 supports whole string items in Tj/TJ, source-font codes mapped by
ToUnicode AND either explicitly listed in a caller's verifiedCodes set or,
when that set is absent, already shown by the same font object on this page.
An explicit empty set authorizes no replacement codes. Resource aliases share
page-use evidence only when their font object ids agree. This interim rule
will be replaced by the parallel canEncode coverage integration later.
Fixed-neighbour compensation includes Tc/Tw/Tz. It preserves
all untouched decoded operators and fonts/resources. Partial string spans,
new/fallback glyphs, Type3/vertical fonts, form targets, quote targets,
clip/ExtGState-dependent targets and unknown state refuse. MCID-only and BMC
spans are editable; enclosing BDC ActualText/Alt/E properties refuse, including
named Properties resources (unresolvable named lists also refuse). Marked
content scope is separate from q/Q; unbalanced marked content refuses.
Unrelated isolated clips and form invocations can remain untouched. The CMap
reader validates supported bfchar/bfrange/codespace sections and refuses
inherited maps; it does not interpret arbitrary PostScript. ToUnicode is an
encoding map, not an outline-coverage proof (the parallel font task owns that).
Longer replacements may overlap neighbours under this fixed-position policy;
fit/overflow UX, partial spans and fallback fonts are the next seams.
